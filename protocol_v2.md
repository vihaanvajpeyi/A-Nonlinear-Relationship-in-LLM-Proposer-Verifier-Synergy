## 1. Research Question

Can standalone behavioral measurements of LLMs predict synergy (or anti-synergy) in
proposer-verifier collaboration pipelines? Specifically: does verifier standalone accuracy
follow a non-monotonic (inverted-U) relationship with collaboration synergy, and do model
metadata features (parameter count, family, instruction tuning, code specialization) predict
verifier effectiveness?

## 6. Prompts

All prompts are frozen. Do not modify after experiments begin.

### 6.1 Phase 1 — Standalone Eval

**Math (all types):**
```
Solve the following problem. Show your reasoning step by step.

Problem: {question}

At the end of your response, write your answer on its own line in this exact format:
Final Answer: {answer}
```

**Coding — code generation:**
```
Write a Python function to solve the following problem. Return only the function definition with no extra explanation.

Problem: {question}
```

**Coding — debugging / output prediction / edge cases:**
```
Answer the following question about Python code. Be concise.

Question: {question}

At the end of your response, write your answer on its own line in this exact format:
Final Answer: {answer}
```

### 6.2 Phase 2 — Proposer

Proposer prompts are identical to Phase 1 standalone eval prompts. The proposer has no
knowledge of the verifier role.

### 6.3 Phase 2 — Verifier

**Math:**
```
You are reviewing another model's solution to a math problem.

Problem: {question}

Proposed solution:
{proposer_response}

Evaluate whether the proposed solution is correct.

Respond in exactly this format:
Verdict: CORRECT or INCORRECT
Reason: {1-3 sentences identifying the key issue, or confirming correctness}
Final Answer: {the correct answer}
```

**Coding — code generation:**
```
You are reviewing another model's Python function.

Problem: {question}

Proposed function:
{proposer_response}

Evaluate whether the proposed function is correct for all inputs, including edge cases.

Respond in exactly this format:
Verdict: CORRECT or INCORRECT
Reason: {1-3 sentences identifying the key issue, or confirming correctness}
Corrected Function:
{raw Python function definition, no markdown fences}
```

**Coding — debugging / output prediction / edge cases:**
```
You are reviewing another model's answer to a Python question.

Question: {question}

Proposed answer:
{proposer_response}

Evaluate whether the proposed answer is correct.

Respond in exactly this format:
Verdict: CORRECT or INCORRECT
Reason: {1-3 sentences identifying the key issue, or confirming correctness}
Final Answer: {the correct answer}
```

## 7. Parsing Rules

### 7.1 Math / debugging / output prediction / edge cases

```python
import re

def parse_standalone(response):
    m = re.search(r'(?i)final answer:\s*(.+)', response)
    if not m:
        return None  # parse failure
    answer = m.group(1).strip()
    if re.search(r'\bor\b|\beither\b|\bdepending\b', answer, re.IGNORECASE):
        return None  # ambiguous answer — treat as parse failure
    return answer

def parse_verifier(response):
    verdict = re.search(r'(?i)verdict:\s*(CORRECT|INCORRECT)', response)
    reason  = re.search(r'(?i)reason:\s*(.+?)(?=\nfinal answer:|\ncorrected function:|$)',
                        response, re.DOTALL)
    answer  = re.search(r'(?i)final answer:\s*(.+)', response)

    if not answer:
        return None  # parse failure

    answer_text = answer.group(1).strip()
    if re.search(r'\bor\b|\beither\b|\bdepending\b', answer_text, re.IGNORECASE):
        return None  # ambiguous — parse failure

    return {
        'verdict':  verdict.group(1).upper() if verdict else None,
        'reason':   reason.group(1).strip() if reason else None,
        'answer':   answer_text
    }
```

### 7.2 Code generation

```python
def parse_standalone_code(response):
    # Extract first function definition found
    m = re.search(r'(def\s+\w+\s*\(.*)', response, re.DOTALL)
    return m.group(1).strip() if m else None

def parse_verifier_code(response):
    verdict  = re.search(r'(?i)verdict:\s*(CORRECT|INCORRECT)', response)
    reason   = re.search(r'(?i)reason:\s*(.+?)(?=\ncorrected function:|$)',
                         response, re.DOTALL)
    function = re.search(r'(?i)corrected function:\s*\n(def\s+\w+.+)',
                         response, re.DOTALL)

    if not function:
        return None  # parse failure

    return {
        'verdict':  verdict.group(1).upper() if verdict else None,
        'reason':   reason.group(1).strip() if reason else None,
        'function': function.group(1).strip()
    }
```

### 7.3 Parse failure policy

- Log the raw response and question ID
- Score the result as `null` (not 0, not 1 — explicitly missing)
- Do NOT retry
- Do NOT overwrite with a retry attempt
- Parse failure rate per model is itself a reported metric

## 8. Scoring Rules

### 8.1 Standalone accuracy

For math / debugging / output prediction / edge cases:
- Compare `parse_standalone(response)` against `question['final_answer']`
- Comparison is case-insensitive, whitespace-stripped
- Numeric answers: exact string match after normalizing (e.g. "3.0" == "3", "1/2" == "0.5" —
  define normalization function explicitly before running)
- Symbolic answers (e.g. "25√3", "49π"): exact string match after Unicode normalization
- Parse failure → score = null

For code generation:
- Run `parse_standalone_code(response)` through test cases in `question['test_cases']`
- Score = fraction of test cases passed (0.0 to 1.0)
- Parse failure or runtime error → score = 0.0

### 8.2 Collaboration outcome

**The collaboration answer is always the verifier's Final Answer (or Corrected Function), full
stop.**

The Verdict field is metadata only and is never used for scoring.

| Proposer | Verifier | Collaboration outcome |
|---|---|---|
| Correct | Echoes correct answer | Correct |
| Correct | Changes to wrong answer | Incorrect |
| Incorrect | Corrects to right answer | Correct |
| Incorrect | Echoes wrong answer | Incorrect |

### 8.3 Derived fields (computed per result row)

```python
changed_answer = (verifier_answer != proposer_answer)  # bool
collaboration_correct = score(verifier_answer, ground_truth)  # bool or float
proposer_correct = score(proposer_answer, ground_truth)
verifier_correct_standalone = score(verifier_standalone_answer, ground_truth)

# Synergy: improvement over best individual
synergy = collaboration_correct - max(proposer_correct, verifier_correct_standalone)
```

### 8.4 Synergy definition

```
synergy(P, V) = accuracy(collaboration(P→V)) − max(accuracy(P), accuracy(V))
```

- Positive synergy: collaboration outperforms both individuals
- Zero synergy: collaboration matches the better individual
- Negative synergy (anti-synergy): collaboration underperforms both individuals

## 9. Retry Policy

**No retries.**

- One attempt per (model, question, role) tuple
- Parse failures are logged and scored null
- Parse failure rate is reported as a model-level metric in the paper

## 11. Stopping Criteria

An experiment run is complete when:
- All (model, question) combinations in Phase 1 have a logged result (null or scored)
- All selected (proposer, verifier, question) combinations in Phase 2 have a logged result
- No result is overwritten or modified after logging
